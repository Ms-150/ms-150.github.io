# 大模型

## 模型的分类

1. 通用语言模型（LLM, Large Language Models）
  + 处理：文本 → 文本
  + 能力：理解、生成、推理、代码、对话
  + 代表：GPT、Claude、Qwen、Llama、DeepSeek

2. 向量模型（Embedding Models）
  + 处理：文本 → 向量
  + 能力：语义检索、RAG、相似度
  + 代表：bge-m3、nomic-embed-text、gte-small
  
3. 多模态模型（Vision/Audio/Video LLM）
  + 处理：图像/音频/视频 → 文本
  + 能力：看图、OCR、图像问答、视频理解
  + 代表：Qwen-VL、LLaVA、Moondream、GPT‑4o

4. 生成式视觉模型（扩散模型 / 文生图模型）
  + 处理：文本 → 图片
  + 能力：文生图、图生图、修复、风格迁移
  + 代表：Stable Diffusion、SDXL、Flux、Midjourney、DALL·E

## 专有名词

+ 权重 = 模型的大脑
+ 量化 = 压缩模型
+ 微调 = 让模型学新技能
+ 参数 = 模型规模 通常以 B (Billion, 十亿) 为单位，代表模型包含的变量总量。
+ 激活参数 = MoE 模型实际用到的部分 MoE 架构就像一个有多个部门的公司，解决一个问题只动用其中 1-2 个部门
+ 训练 = 学习阶段（FP32/FP16/BF16）
+ 推理 = 使用阶段（FP8/INT8/INT4） 此时模型不再进化，只需计算结果。所以可以用低精度（INT4）来换取速度
+ token = 模型的最小输入单位
+ 上下文长度 = 模型的记忆范围

## 权重 Weights

权重 = 模型的大脑

权重 = 模型学到的所有参数，是模型的“知识”。

## 量化 Quantization

量化 = 压缩模型

量化 = 把模型从“高清”压成“省流版”，让它更小、更省显存，但尽量不变笨。

就像视频有 4K、1080p、720p、360p

模型也有 FP32、FP16、FP8、INT8、INT4、Q4、Q2。

| 精度名称      | 缩写/量化等级  | 每个参数占用 (Bytes) | 压缩率 (对比FP32) | 画质类比   | 运行效果与建议                                                |
| ------------- | -------------- | -------------------- | ----------------- | ---------- | ------------------------------------------------------------- |
| `FP32`        | Full Precision | 4 字节               | 1x                | 原片 (RAW) | 仅用于模型训练，本地运行极度浪费内存                          |
| `FP16`/`BF16` | Half Precision | 2 字节               | 2x                | 4K 蓝光    | 本地运行的“天花板”，16GB 内存仅能跑起 7B 模型                 |
| `FP8`/`INT8`  |                | 1 字节               | 4x                | 1080P      | 16GB 内存可流畅运行 8B-10B 模型                               |
| `Q6_K`        | 6-bit          | ~0.8 字节            | 5x                | 1080P      | 极佳的折中方案，肉眼难辨的精度损失                            |
| `Q4_K_M`      | 4-bit          | ~0.6 字节            | 6.6x              | 720P       | 标清 本地运行主力，16GB 内存可运行 14B 模型，速度快且智商在线 |
| `Q4_K_S`      | 4-bit          | Small ~0.5 字节      | 8x                | 480P       |
| `Q2_K`        | 2-bit          | ~0.3 字节            | 13x               | 360P       | 甚至更低 极限压缩，模型会经常胡言乱语，不推荐使用             |

### FP 浮点量化 / INT 整数量化

| 项目     | FP 量化                    | INT 量化                  |
| -------- | -------------------------- | ------------------------- |
| 数字表示 | 浮点（科学计数法）         | 整数（固定范围）          |
| 动态范围 | **大**（能处理 outliers）  | **小**（需 scale）        |
| 精度     | 低比特下更稳（FP4 > INT4） | 8bit 下更强（INT8 > FP8） |
| 硬件效率 | 较低                       | **最高**                  |
| 适用场景 | 大模型推理、训练           | 高效推理、边缘设备        |

#### + `FP`（Floating Point 浮点）量化：像科学计数法

典型格式：`FP16`、`FP8`、`FP4`

保留“科学计数法结构”，动态范围大、对异常值更稳

适合大模型推理，因为激活分布跨度大  

#### + `INT`（Integer 整数）量化：固定范围的整数
典型格式：`INT8`、`INT4`

INT（整数量化）更“死板”，范围小但计算效率更高

适合高效推理，硬件效率更高  

### GGUF 里的特殊后缀

Hugging Face 上看到的 特殊后缀`Q4_K_M`、`Q5_K_S` 是什么意思？

#### Q + 数字
量化比特数

| 后缀      | 大小  | 解释                  |
| --------- | ----- | --------------------- |
| `Q8`      | 8-bit | 质量最高 文件最大     |
| `Q6`      | 6-bit | 接近原始 FP16         |
| `Q5`      | 5-bit | 质量很好              |
| `Q4`      | 4-bit | 最常用 质量与体积平衡 |
| `Q3`/`Q2` |       | 极限压缩 质量下降明显 |

| 后缀          | 解释                                                             |
| ------------- | ---------------------------------------------------------------- |
| `_K`          | 代表使用了 K-Quant 算法，是目前 llama.cpp 最主流的高效量化算法。 |
| `_S` (Small)  | 压缩得更狠，体积更小。                                           |
| `_M` (Medium) | 最推荐，平衡感最好。                                             |
| `_L` (Large)  | 尽量保留精度，体积稍大。                                         |

| 部分 | 含义                                          |
| ---- | --------------------------------------------- |
| `Q`  | Quantized（量化模型）                         |
| `4`  | 4-bit 精度（越小越省内存）                    |
| `_K` | K-Quant（高级分组量化，比旧式 Q4_0 更高质量） |
| `_M` | Medium（中等变体：质量与大小平衡）            |

## 微调 Fine‑tuning

微调 = 在原模型基础上继续训练，让它适应新任务。

### 常见微调方式

全量微调（Full Fine‑tune）、LoRA（最常用）、QLoRA、

#### 1. 全量微调（Full Fine‑tune）
+ 修改所有权重
+ 显存需求巨大
+ 效果最好
+ 大模型几乎没人这么做

#### 2. LoRA（最常用）
+ 只训练少量“适配层”
+ 显存需求极低
+ 效果很好
+ 可以叠加多个 LoRA

#### 3. QLoRA
+ 在量化模型上做 LoRA
+ 让 24GB 显卡也能微调 70B 模型

微调的本质：

让模型从“通用”变成“专精”。

## Token（标记）——模型的最小输入单位

模型不是按“字”处理，而是按 token。

例如：
+ “我喜欢你” → 可能是 3 个 token
+ “DeepSeek” → 可能是 1 个 token
+ 英文更容易被压成少量 token

上下文长度（context length）就是模型一次能处理多少 token。

## Context Length（上下文长度）——模型的记忆长度

例如：
+ Llama 3.1 → 128K
+ DeepSeek‑V4‑Flash → 1M
+ GPT‑4o → 128K

上下文越大，模型能处理的文档越长。

## Embedding（向量）——文本的数字表示

Embedding = 把文本变成向量
用于：
+ 搜索
+ RAG
+ 相似度匹配
+ 推荐系统

# 模型的发展
## 阶段

1. Prompt（提示工程）

模型按指令回答，没有记忆、没有流程、没有外部知识。

2. RAG（知识增强）

模型能访问企业知识库，回答更准确、更业务化，但仍然是“问答系统”。

3. Agent（智能体）
核心: 智能体 (AI Agents) + MCP + Skill
模型能拆解任务、调用工具、执行流程，成为“能做事的系统”，而不是“回答问题的工具”。

## 名词

+ `prompt`  提示/指令
+ `context` 上下文/素材
+ `Harness` “马具”或“安全带”，引申为“控制、利用、治理”

如果 `Prompt` 是“灵魂”，`Context` 是“原材料”，那么 `Harness` 就是那套让灵魂能精准加工原材料的“模具”或“传送带”。

### 1. 基础资源层

#### Prompt

+ 定义: 告诉 AI“要做什么”以及“扮演什么角色”。
+ 内容: 包含角色设定（Role）、任务描述（Task）、输出格式要求（Output Format）和语气风格（Tone）。
+ 类比: 它是厨师（角色）和菜谱（步骤）。

#### Context

+ 定义: 告诉 AI“基于什么信息”来执行任务。
+ 内容: 包含背景资料、用户上传的文档、历史对话记录、检索到的知识片段（RAG 内容）。
+ 类比: 它是放在案板上的食材（原始数据）。

### 2. 治理与框架层

#### Harness

+ 结构化挂载（Mounting）
    Harness 负责定义 Prompt 和 Context 如何拼接。例如，它会规定“永远将最新的上下文放在 Prompt 的末尾”，或者“在长文本中间插入特定的锚点以防止模型分心”。
+ 动态注入（Injection）
    在程序自动化中，Harness 是那个模板引擎。它通过变量（如 {{context}}）将外部数据实时动态地灌入预设的 Prompt 框架中。
+ 护栏与约束（Guardrails）
    它是对输入输出的“围栏”。比如限制 Context 的最大 Token 长度（避免溢出），或者在 Context 两端加上特定的分隔符（如 ### Context Start ###），以防模型分清不清哪些是指令，哪些是参考资料。
+ 逻辑触发（Orchestration）
    它决定了何时调用这些上下文。例如，在多轮对话中，Harness 会判断哪些 Context 是过期的，哪些是需要保留的“精华”，从而维持逻辑的连贯性。

### 3. 能力与协议层 (MCP & Skill)

#### MCP (Model Context Protocol - 模型上下文协议)

+ 定义: 由 Anthropic 提出的开放协议，旨在标准化 AI 模型与外部数据及工具之间的连接方式。
+ 在 Harness 中的位置: 它是 Harness 的工业级标准。
+ 核心逻辑: 以前每个应用都要为 AI 单独写一套获取数据的代码（比如对接 GitHub API、SQL 数据库）；有了 MCP，只要数据源提供一个 MCP Server，任何支持该协议的 Agent 都能直接读懂并挂载。
+ 类比: 它是电脑上的 USB 接口。不管你是鼠标、键盘还是硬盘（数据/工具），只要是 USB 接口，插上电脑（模型）就能用。

#### Skill (技能/工具)

+ 定义: Agent 能够执行的具体功能模块，在 Dify 中通常表现为“工具（Tools）”。
+ 内容: 包含一个具体的执行函数（如 get_weather）和一段语义描述（告诉模型这个工具是干嘛的、需要什么参数）。
+ 核心逻辑: 模型并不直接运行代码，而是通过阅读 Skill 的描述，决定“现在需要调用这个函数”，并生成符合要求的参数。
+ 类比: 它是厨师手中的各类厨具。切菜用刀，加热用微波炉。每个工具解决一个具体问题。

### 4. 系统集成层

#### Agent (智能体) —— 拥有大脑的“执行主体”

+ 定义: 以大模型为核心，能够自主理解目标、拆解步骤、调用 Skill 并利用 MCP 动态获取 Context 的系统。
+ 核心逻辑: Agent 不再是简单的“一问一答”，而是“思考——行动——观察——再思考”的循环（Reasoning Loop）。
+ 类比: 它是一个全能管家。你只说“我要开派对”，他会自己去查天气（Skill）、看你的通讯录（Context/MCP）、订餐厅（Skill），最后给你结果。
